# readDoc Tool Usage

## Purpose
The `readDoc` tool reads the full content of a document. The returned content includes any **pending changes** that the user has not yet approved or rejected, reflecting what the user will see after approval.

## Parameters
- `documentId` (optional): The ID of the document to read. If omitted, reads the currently active document.
- `search` (optional): Search by title fragment to find a document (case-insensitive). Cannot be used together with `documentId`.

## How to Use Output for Subsequent Edits
The document content is returned as raw markdown without any line number prefixes. For example:
```
# Document Title

## Section 1
Content here...
```

When extracting text for `editDoc`:
1. Copy the exact text you want to replace **verbatim** — including whitespace, indentation, and line endings
2. There are no line numbers in the output — use the raw text as-is

## Best Practices
- Use `readDoc` before `editDoc` to get the current document content
- If you need to find the right document, use `searchDocs` or `listDocs` first to get the document ID
- Read the full document when you need context, or read specific sections by searching the output
- After making edits, read the document again to verify changes were applied

## Important
- The content includes pending changes (unapproved edits), so it reflects the document's soon-to-be state
- Very large documents (over 2000 lines) will be truncated with an indicator
- Reading a document costs tokens - be strategic about when to read full vs partial content
